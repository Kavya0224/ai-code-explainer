# AI Code Explainer

AI Code Explainer is a full-stack tool that takes any public GitHub repository URL, clones it, scans its source files, and generates AI-powered explanations, a dependency graph, an auto-classified architecture breakdown, and a lightweight semantic search over the codebase — all so you can understand an unfamiliar repo faster.

## Features

- **Repository analysis** — paste a GitHub URL and the backend clones it (shallow clone) and scans it for source files.
- **AI file explanations** — the first few scanned files are sent to a local LLM, which returns the purpose, main functions, dependencies, and notes for each file.
- **Dependency graph** — uses [madge](https://github.com/pahen/madge) to map how files depend on one another.
- **Architecture classification** — automatically buckets files into API layer, business logic, data layer, infrastructure, and other, based on path/naming heuristics.
- **Semantic-ish search** — tokenizes file contents and scores them against a search query using Jaro–Winkler similarity to surface the most relevant files.

## Tech Stack

**Frontend**
- React 19 + Vite
- Axios for API calls

**Backend**
- Node.js + Express 5
- [simple-git](https://github.com/steveukx/git-js) for cloning repositories
- [madge](https://github.com/pahen/madge) for dependency graph generation
- [natural](https://github.com/NaturalNode/natural) for tokenization and similarity search
- Axios (used to call a local LLM server for explanations)

## Prerequisites

- Node.js (v18+ recommended)
- Git installed locally
- A local LLM server (e.g. [Ollama](https://ollama.com/)) running on `http://localhost:11434` with a model named `llama3` pulled, since file explanations are generated by calling this endpoint

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/Kavya0224/ai-code-explainer.git
cd ai-code-explainer
```

### 2. Backend setup

```bash
cd backend
npm install
```

Create a `.env` file in `backend/` if you want to customize the port:

```
PORT=5000
```

Start the backend:

```bash
node server.js
```

The API will be available at `http://localhost:5000`.

> **Note:** `repoService.js` currently hardcodes the Git binary path for Windows (`C:\Program Files\Git\cmd\git.exe`). If you're on macOS/Linux, update or remove the `binary` option in `simpleGit({...})` before running.

### 3. Frontend setup

```bash
cd frontend
npm install
npm run dev
```

The frontend will be available at the Vite dev server URL (default `http://localhost:5173`), and it talks to the backend at `http://localhost:5000/api`.

## API Reference

### `POST /api/repo/analyze`

Clones and analyzes a GitHub repository.

**Request body:**
```json
{
  "repoUrl": "https://github.com/owner/repo"
}
```

**Response:**
```json
{
  "message": "Repository cloned successfully",
  "data": {
    "repoName": "repo",
    "totalFiles": 42,
    "files": [
      { "path": "...", "explanation": "..." }
    ],
    "dependencyGraph": { "...": ["..."] },
    "architecture": {
      "apiLayer": [],
      "businessLogic": [],
      "dataLayer": [],
      "infrastructure": [],
      "other": []
    }
  }
}
```

### `POST /api/search`

Searches the most recently analyzed repository's files.

**Request body:**
```json
{
  "question": "Where is authentication implemented?"
}
```

**Response:**
```json
{
  "message": "Search results",
  "results": [
    { "file": "path/to/file.js", "score": 0.87 }
  ]
}
```

## How It Works

1. A GitHub repo URL is submitted from the frontend.
2. The backend shallow-clones the repo and recursively scans it for supported source files (`.js`, `.ts`, `.py`, `.java`, `.cpp`, `.c`, `.cs`, `.go`, `.rb`), skipping folders like `node_modules`, `.git`, `dist`, and `build`.
3. The first few scanned files are sent to a local LLM (via `http://localhost:11434/api/generate`) to generate a plain-English explanation of each.
4. `madge` builds a dependency graph of the codebase.
5. The dependency graph is classified into architecture layers using path-based heuristics.
6. All results are indexed for lightweight text search, so you can query the repo afterward via `/api/search`.

## Limitations / Known Notes

- Only the first 5 scanned files are sent for AI explanation (for speed).
- Code sent to the AI model is truncated to 3000 characters per file.
- Search uses Jaro–Winkler string similarity on tokenized text rather than true embeddings-based semantic search.
- Requires a local LLM server running the `llama3` model; there's no cloud AI provider wired in by default despite the `openai` dependency being present.
- The Git binary path in `repoService.js` is currently hardcoded for Windows.
